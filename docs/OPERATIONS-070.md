# Vortex MC 0.7.0 — runtime administration

Server **Configuration → Resources** and the creation form offer shared host resources or fixed CPU/RAM limits. Linux cgroup v2 must be delegated to the panel service. The installer sets `Delegate=cpu memory`; the native launcher uses a Bash gate before execution. Limits are caps, not reservations; parent unit limits still apply. A fixed server never silently starts with unlimited shared resources when enforcement fails. See [RESOURCE-CONTROL.md](RESOURCE-CONTROL.md).

**World rules** is separate from the Worlds data library. Read values from the running Bedrock process, change selected rules, and apply them. Keep inventory, daylight/weather cycles, mob griefing, PvP, coordinates, regeneration, drops and other supported rules are typed and validated. The request includes the current world revision and expected values. A restart/world change or another administrator's change rejects stale requests. Values are confirmed by native output; incomplete batches show individual results. Gamerules persist in the world and do not require cheats.

**Players → Actions** targets an observed online connection, not an arbitrary selector. Available actions include Give, Kill, Kick, Heal, Gamemode, Teleport, Operator and Remove operator. Give/Kill/Heal/Gamemode/Teleport require cheats. Vortex never enables cheats automatically. Commands include the selected name, XUID and connection identity; reconnects invalidate the selection. Explicit confirmation is required. Command submission and native confirmation are distinct states. Game messages use the server's EN/VI setting, with EN the default.

**Settings → Log storage & retention** controls activity and finished jobs by age, entry count and bytes; managed console files have age/byte limits, and their memory/tail views also have an entry limit. Defaults are 30 days; activity 1,000 entries/2 MiB; finished jobs 200 entries/4 MiB; each console file 2 MiB. The console in memory and its disk-write queue are also bounded. Native line fragments are UTF-8 bounded. When a console file reaches its byte ceiling, cleanup retains the newest rows at about 75% capacity to leave append headroom. Quiet under-budget maintenance does not rewrite unchanged files. Known retention evictions, unread legacy bytes, processed inputs and materialized new entries are reported separately. Active jobs and unresolved recovery records are protected, and can exceed the history budget until resolved. Clearing history requires confirmation and preserves these records. Export is available before clearing. Linux journal, arbitrary server files and custom logging plugins are outside this policy.

Operation popups show overall workflow milestones separately from actual download bytes. A package download can reach 100% while verification/install is still running. Overall progress reaches 100 only after successful completion. Unknown content length has no invented download percentage. Upload indicators use actual browser transfer events, then show server-side processing. Closing a progress popup leaves its job available through Notifications.

Console events are rendered in batches with keyed rows and a bounded browser window. Navigation/dialog motion uses short opacity/transform transitions and honors Reduce motion. Fields, drafts and selected files survive language changes. Changes made while an earlier save is pending remain visible as unsaved changes.

Design and implementation references: [Apple progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators), [Apple motion](https://developer.apple.com/design/human-interface-guidelines/motion), [web.dev animation performance](https://web.dev/articles/animations-and-performance), [Microsoft Bedrock gamerule reference](https://learn.microsoft.com/en-us/minecraft/creator/commands/commands/gamerule?view=minecraft-bedrock-stable), [Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html).
